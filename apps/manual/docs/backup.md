# 备份配置

## 什么时候需要备份

以下操作前都建议先备份：

- 第一次使用还原或 Wooting 导入之前；
- 打算大改键位、灯效、行程或高级键之前；
- 更新脚本、换浏览器配置文件、换电脑之前；
- 想保留一套“确定可用”的配置作为回退点。

::: warning 备份是手动操作
还原和 Wooting 导入都不会自动备份设备现有配置。没有备份就写入时，被覆盖的设置只能
重新手动配置。
:::

## 备份步骤

1. 按官方驱动页面的流程连接键盘（正常授权 HID 设备）。
2. 点击主面板的 **备份**。
3. 等待读取完成。传输期间按钮会暂时禁用，请勿关闭页面。
4. 浏览器下载 `zmeow-config-<YYYYMMDD-HHMMSS>.json`，例如
   `zmeow-config-20261117-223501.json`。
5. 查看日志中的摘要，例如：
   `备份完成，已开始下载 JSON（3 个重映射层、61 个键色、12 个行程键、4 项特性）`。

备份过程中脚本同样会短暂切换到安全视图并隔离官方页回包，日志里出现对应的
“已把官方页切换到安全视图”“已隔离官方页收包”提示属于正常现象。

## 备份文件里有什么

备份是一个普通 JSON 文档（格式标识 `zmeow.keyboard-config`，当前版本 `1`），包含：

| 字段 | 内容 |
| --- | --- |
| `createdAt` | 备份创建时间（ISO-8601） |
| `product` | 产品 id、名称、VID / PID |
| `layout` | 备份时的布局：`compact65` 或 `extended79` |
| `firmwareVersion` | 固件版本，仅用于诊断 |
| `remap.layers` | 每个 Fn 层的重映射表（层 → 键 → HID usage） |
| `light` | 灯效状态：模式、亮度、速度、方向、颜色等 |
| `keyColors` | 单键颜色 |
| `travel` | 逐键行程配置：触发点、快速触发、按下 / 松开行程等 |
| `features` | 高级键列表：SOCD、RS、MT、TGL、MPT、END、DKS 等 |
| `misc` | 杂项：Win 锁状态、灯光休眠时间 |
| `warnings` | 备份时产生的非致命提示（通常为空） |

::: info 不包含设备标识
备份**不包含**设备序列号（SN）和 `boardId`，但包含完整的键位、灯效和行程设置。
仍请妥善保管，不要随意上传到公开位置。
:::

## 读取警告

备份会尽量容错：个别层或高级键列表读取失败时，会跳过该项并记录 `警告`，而不是让整个
备份失败。

| 日志警告 | 含义 | 影响 |
| --- | --- | --- |
| `Could not read the key map of layer N` | 第 N 层读取失败 | 该层没有写入备份；还原时不会改动这一层 |
| `Could not read the feature list` | 高级键列表读取失败 | 备份标记为 `featuresRead: false`；还原时保留设备现有高级键，不会清空 |
| 行程 / 灯效读取超时 | 共享句柄繁忙或设备无响应 | 对应项目可能缺失 |

如果备份出现警告：

1. 先断开再重新连接键盘，或刷新驱动页后重试；
2. 确认没有其他页面 / 工具同时打开同一个 HID 句柄；
3. 重试后仍有警告时，把这台设备的固件版本和日志保留下来，用于反馈。

## 跨布局备份

备份会记录拍摄时的布局。把 65 键布局的备份还原到 79 键设备（或反过来）时，脚本会
先弹出“布局不一致”确认框，只写入两种布局共有的按键。详见[还原配置](/restore)。
