# 常见问题

## 快速排查表

| 现象 | 最可能的原因 | 先做什么 |
| --- | --- | --- |
| 面板完全不出现 | 脚本未启用、域名不匹配、MV3 注入失败 | 检查 Tampermonkey 与脚本状态，刷新页面 |
| 状态停留在“未连接（等待设备）” | 官方页尚未连接键盘 | 在官方驱动页连接键盘 |
| 状态是“通过 tap 代理连接” | 页面指纹或固件不在已知基线 | 查看日志原因，更新脚本后重试 |
| 备份出现警告 | 共享句柄繁忙、某层读取超时 | 关闭其他页面 / 工具，重连后重试 |
| 还原后个别设置没生效 | 固件丢写、布局跳过 | 查看 `警告` 行，重试一次还原 |
| Wooting 导入取数失败 | 网络、CORS、限流 | 检查网络与 `api.wooting.io` 权限，稍后重试 |
| 更新后仍是旧版本 | CDN 缓存未刷新 | 从 GitHub Release 手动安装 |
| 键盘没有响应 | 同时打开了多个 HID 句柄 | 只保留一个页面 / 工具，重连设备 |

## 面板没有出现

1. 确认 Tampermonkey 已启用，并且 **Better ZetsuMeow Driver** 脚本处于启用状态。
2. 确认地址是 `https://driver.zetsumeow.com/`。发布版只匹配这个域名，`http://`、`www.` 或其他域名都不会注入。
3. 使用 Tampermonkey MV3 版本时，开启 **Allow User Scripts**，并把 Content Script API 设为 **UserScripts API Dynamic**。
4. 刷新驱动页。脚本在 `document-start` 注入，页面加载完成后才会显示面板。
5. 打开浏览器开发者工具，检查 Console 是否有脚本错误；再检查 Tampermonkey 的脚本是否真的在该页面运行。
6. 仍不出现时，重新安装最新 Release。

## 状态一直是“未连接（等待设备）”

面板已经注入，但官方页面还没有建立设备连接：

- 在官方驱动页按正常流程连接键盘；
- 检查浏览器的 HID 设备授权，必要时重新授权；
- 如果官方页面本身也连不上键盘，先解决官方驱动的问题。

## 状态是“通过 tap 代理连接”

这表示脚本仍能观察页面连接，但官方页面资源哈希或设备固件不在当前脚本的已知基线内，
脚本进入只读观察模式。常见原因：

- 官方驱动页面更新了，脚本尚未适配；
- 键盘固件版本不在测试列表内；
- 页面加载不完整，指纹没有算出来。

处理方式：

1. 查看日志中的 `原因：…` 一行；
2. 刷新页面，重新连接键盘；
3. 更新到最新脚本版本；
4. 如果更新后仍是只读，先只做备份，等待脚本适配；不要依赖此状态下的写入。

## 状态是“已禁用”

说明当前环境无法建立 tap，或产品表 / 协议不匹配：

- 换用桌面版 Chrome / Edge；
- 确认页面是 HTTPS 或 `localhost`，`file://` 页面没有 WebHID / Web Serial；
- 确认官方页面仍是受支持的产品；新增型号需要脚本适配。

## 备份出现警告

备份会跳过读取失败的层或高级键列表，而不是整体失败：

- `Could not read the key map of layer N`：该层不会写入备份；
- `Could not read the feature list`：备份不会在还原时清空高级键。

先关闭其他可能持有 HID 句柄的页面或程序，断开并重新连接键盘，然后重试。
仍然失败时，记录固件版本和日志用于反馈。

## 还原后设置没有生效

1. 查看日志中是否有 `警告：…`，确认哪些项被跳过或重试后仍失败；
2. 确认还原期间没有第二个页面 / 工具同时打开键盘；
3. 确认备份与设备布局一致；跨布局时只有重叠按键会写入；
4. 对同一份备份再执行一次还原，固件偶发丢写可能在第二次写入时成功；
5. 如果只有灯效或高级键没有变化，检查备份本身是否包含这些内容（见[备份文件里有什么](/backup#备份文件里有什么)）。

## 布局不一致怎么办

- 对话框会显示重叠按键数 `shared` 和被跳过的按键数 `skipped`；
- 点击 **同意还原 / 同意导入** 才会写入，且只写入重叠键；
- 点击 **取消** 不会写入设备，可以安全退出后换用匹配布局的备份或 profile。

## Wooting 导入失败

| 日志关键字 | 处理 |
| --- | --- |
| 无法获取分享配置 / 网络 | 检查网络；确认 Tampermonkey 允许访问 `api.wooting.io`；稍后重试 |
| 429 / 限流 | 分享接口约 40 次 / 10 秒，等待后重试 |
| 分享码无效 | 重新在 Wootility 生成分享码；确认没有多余空格 |
| 型号不支持 | 只支持 60HE / 80HE 家族，详见[支持的型号](/wooting#支持的型号) |
| 配置版本过新 | 更新脚本；当前支持 profile schema 9–15 |
| 布局不一致 | 确认后只写入重叠键，或取消 |

## 导入后灯效或高级键没有变化

这是导入的补丁语义，不是失败：

- profile 没有静态逐键颜色时，不改写设备灯效；
- profile 没有高级键时，不清除设备现有高级键；
- 转换提示中会列出被跳过的项目，例如动态 RGB、DKS、gamepad。

## 刷新页面后要重新选择设备

写入成功后的“立即刷新”会重新加载驱动页。浏览器不会自动恢复页面的设备选择状态，
通常需要重新选择 / 连接设备。这是正常行为，不是配置丢失。

## 键盘无响应或按键异常

- 同一时间只保留一个页面或程序持有 HID 句柄；关闭其他驱动页、调试工具和脚本页面；
- 在官方驱动页断开并重新连接键盘；
- 必要时拔插键盘或重启浏览器；
- 如果设备停留在按键测试状态，断开连接会由 SDK 补发结束命令；仍异常时重新连接设备。

## 更新后还是旧版本

- 在 Tampermonkey 中执行一次“检查更新”；
- 确认 `@updateURL` 可访问；jsDelivr 缓存尚未刷新时，从 GitHub Release 手动安装；
- 确认脚本列表里没有两个同名条目，删除旧条目后重试。

## 支持哪些浏览器

只支持桌面版 Chrome / Edge。Firefox、Safari、移动端浏览器不支持 WebHID / Web Serial，
因此无法使用本脚本。

## 如何反馈问题

提交 issue 时请提供：

- 脚本版本（Tampermonkey 中的 `@version`）；
- 浏览器名称和版本；
- 键盘型号、固件版本、布局（65 / 79 键）；
- 复现步骤和面板日志中的关键行；
- 涉及 Wooting 导入时，说明型号和 profile schema。

请勿粘贴设备序列号、Wooting 分享码或其他敏感信息。更多数据说明见[数据与隐私](/privacy)。
