# 导入 Wooting 配置

脚本可以把 Wootility Web 的 profile 迁移到 Zetsu 键盘。导入通过 **Wooting 分享码** 取数，
在本地转换成备份格式后，走与[还原配置](/restore)相同的写入流程。

::: warning 导入前先备份
导入是**补丁式**写入，不会读取或备份设备现有配置。需要保留当前配置时，请先执行
[备份](/backup)。
:::

## 支持的型号

| 型号 | `target.device` | Zetsu 目标布局 |
| --- | --- | --- |
| Wooting 60HE / 60HE AVR / 60HE+ / 60HE v2 | 4 / 5 / 9 / 11 | `compact65`（65 键） |
| Wooting 80HE / 80HE+ | 10 / 12 | `extended79`（79 键） |

以下型号**不支持**，也不会做重叠键的部分迁移：

- Wooting One（0）
- Wooting Two（1）
- Wooting Two HE（3 / 6）
- Wooting UwU（7 / 8）
- Wooting Lekker 模块（2）
- 未知 device id

型号检查发生在设备写入之前。不支持的型号会直接报错，不会进入还原流程，也不会改动设备。

## 获取分享码

1. 在 [Wootility Web](https://wootility.io/) 中打开要迁移的键盘 profile。
2. 使用 Wootility 的分享功能生成 profile 分享码（profile code）。
3. 回到 ZetsuMeow 驱动页，按官方驱动页面的流程连接键盘（正常授权 HID 设备）。
3. 在面板 **导入 Wooting 配置** 一栏粘贴分享码，点击 **导入**。

分享码会发送到 Wootility 的分享接口（`api.wooting.io`）以取回 profile。请求由
Tampermonkey 的 `GM_xmlhttpRequest` 发出，因此不受驱动页 CORS 限制；该接口有大约
**40 次 / 10 秒**的限流，触发限流时会提示网络 / 限流失败，稍等后重试即可。

## 导入步骤

1. 连接键盘，确认面板为 **已连接**。
2. 在 **导入 Wooting 配置** 输入框粘贴分享码，点击 **导入**。
3. 等待日志依次出现：
   - `已获取 Wooting 配置 …，开始写入`；
   - `Wooting 配置已转换为备份文档：…，开始还原`；
   - 安全视图切换与回包隔离提示。
4. 如果 profile 布局与键盘布局不同，会先弹出 **布局不一致** 对话框；
   点击 **同意导入** 继续，点击 **取消** 不写入设备。
5. 等待完成摘要：
   `Wooting 配置还原完成：重映射 …、键色 …、行程 …`。
6. 检查 `警告：…` 行和“Wooting 配置转换提示”行，了解哪些项目没有被导入。
7. 在“刷新页面”对话框中选择是否立即刷新。

## 会导入什么

| 项目 | 支持度 | 说明 |
| --- | --- | --- |
| 基础层重映射 | 完全 | 跳过没有实际变化的恒等项；未知键记入警告 |
| Fn 层重映射 | 部分 | 固定导入基础层 + 第一层 Fn（layer 0/1） |
| 静态逐键 RGB | 完全 | 只读取静态 `rgb.kbdArray`；亮度从 0–255 映射到 0–10 |
| 触发点 / 快速触发 | 完全 | 支持全局和逐键；0.1–4.0mm |
| 自定义触发点 | 完全 | 兼容不同 profile 版本的单位格式 |
| SOCD | 完全 | 支持中立、第一键优先、第二键优先、后输入优先 |
| Rappy Snappy (RS) | 完全 | 第二键 + 触底行为；`socd` 模式忽略 |
| Mod Tap (MT) | 完全 | 按住键 / 点按键映射到 Zetsu 对应字段 |
| Toggle (TGL) | 完全 | 目标键映射到 Zetsu 对应字段 |

两键功能（SOCD / RS）的键对规则：

- 同一组无序键对只导入一次；
- 一个键只能出现在一个同功能键对中；
- 自配对、重复键对和冲突条目会跳过并记入警告；
- SOCD 与 RS 使用独立的键对集合。

## 不会导入什么

| 项目 | 原因 |
| --- | --- |
| DKS | 当前 SDK 没有 DKS 写入命令，不能等价成其他功能 |
| RGB 动态效果 / 多层颜色 | 只导入静态逐键颜色 |
| gamepad / lightbar | Zetsu 没有对应设置 |
| tachyon / digital mode / tick rate | Zetsu 没有对应设置 |
| profile 元数据 | 只写入警告，不写设备 |
| ISO / JIS 额外键 | 当前布局没有对应键位时跳过 |
| AKC 中 `layer != 0` 的条目 | AKC 不支持按层作用域 |
| 第 2 层 Fn（Fn2）及更多层 | Zetsu 只有一个 Fn 层，固定导入 layer 0/1 |

## 数值与单位口径

导入会按 profile schema 自动识别单位，尽量还原 Wooting 的手感：

- 当前 Wootility Web profile schema 为 **15**；支持 **9–15**；
- schema **< 9** 尽力导入并记录 legacy 警告，不推测旧版 remap / DKS 结构；
- schema **> 15** 直接拒绝，提示配置版本过新，需要先更新脚本；
- **快速触发**：Wooting 的“按下 / 再触发”灵敏度映射到按下行程，“松开 / 重置”映射到
  松开行程；全局和逐键都支持；
- **快速触发开关**：单键 `false` 会显式关闭，并优先于全局开关；
- **快速触发严格触发范围**：按其开关映射到快速触发输出行程；
- **防误触死区**：Wooting 没有 Zetsu 的顶部 / 底部死区，导入时两者固定写 **0**，
  避免 0.1mm 的触发点被默认 0.2mm 死区吞掉。

## 布局差异

转换始终以 profile 的原生布局为目标（60HE 家族 → `compact65`，80HE 家族 → `extended79`），
跨布局交给还原流程处理：

- 布局不一致时弹出确认框，只写入重叠按键；
- 60HE 左上角的 Esc 在 `compact65` 中没有对应键位，会被跳过，**不会**改写成反引号；
- ISO / JIS 的额外键、没有 Zetsu cell 的键会跳过并记入警告。

## 导入是补丁，不是全量恢复

与普通还原不同，Wooting 导入会尽量保留设备上已有、但 profile 中没有的内容：

- profile 没有静态键色时，**不改写设备灯效**；
- profile 没有高级键时，**不清除设备现有高级键**；
- 导入不会清除其他未涉及的高级键，属于“叠加配置”。

## 导入失败时

| 日志 | 常见原因 | 处理 |
| --- | --- | --- |
| `无法获取分享配置 …` | 网络不通、CORS 拦截或限流 | 检查网络；确认 Tampermonkey 允许访问 `api.wooting.io`；稍后重试 |
| `分享码无效或配置不存在` | 分享码输错、过期或已删除 | 重新生成分享码 |
| `该 Wooting 型号不支持导入` | Wooting One / Two / UwU / Lekker 等 | 换用受支持的 60HE / 80HE profile |
| `该 Wooting 配置版本过新` | profile schema > 15 | 更新脚本到最新版本，或降低 Wootility profile 版本 |
| 布局不一致对话框 | 60HE ↔ 80HE 或设备布局不同 | 确认后只写入重叠按键，或取消 |
